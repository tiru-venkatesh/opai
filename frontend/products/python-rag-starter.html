How it works

Retrieval you can read, not a black box.

  1. Parse

    PDF (page by page), DOCX, TXT, Markdown and CSV. Scanned PDFs are rejected with a clear message instead of silently returning nothing.

  2. Chunk & embed

    Paragraph-first chunks with overlap. Uses fastembed if installed, or a built-in fallback that needs no download.

  3. Hybrid search

    Embedding similarity plus BM25, merged with rank fusion, then MMR so the top results aren't near-duplicates.

  4. Cited answer

    The model sees numbered passages and must cite them. Citations that don't exist are stripped. No LLM? You still get cited extracts.

The kit tells you when retrieval is wrong.

Pro includes an evaluation harness. Write questions and the passages that should answer them; it reports whether the right passage came back. Output on the bundled sample (3 documents, 18 questions, built-in fallback embedder, no model download):

opai-rag-eval --chunk-sizes 300,600,900
 chunk  docs   hit@1   hit@5    MRR  abstain
   300     3    0.80    0.93   0.85     0.67
   600     3    0.80    1.00   0.87     1.00
   900     3    0.67    0.87   0.75     1.00

This sample is tiny and exists to show how the tool works. Your documents will score differently, which is exactly why you run it on them. “Abstain” is the share of off-topic questions where nothing was returned.

Know before you buy

What it doesn't do.

No OCR

Scanned PDFs are rejected with a message. Run OCR first.

English-centric

The tokenizer and default embedder are tuned for English text.

Lite scans every chunk

Fine up to tens of thousands of chunks. Beyond that, use Pro's Postgres or Chroma store.

Rate limit is per process

With several workers, put a gateway limit in front for an exact global cap. The daily quota is exact.

FAQ

Questions before you buy.

Do I need an OpenAI or Anthropic key?

No. Without an LLM you get extractive answers: the most relevant sentences with citations. Add ANTHROPIC_API_KEY for written answers with Claude, or pass any function (system, user) → text to use a different model.

What can I do with the licence?

Pro is licensed to one named developer. You may modify it and use it in commercial products and hosted services, including for your clients. You may not resell, share or publish the kit's source. Read LICENSE.txt in the repository before you buy. Lite is MIT.

Which Python versions and databases?

Python 3.10 or newer (the test suites are run on 3.12). Lite uses SQLite. Pro adds Postgres with the pgvector extension, tested on Postgres 16 (the pgvector/pgvector:pg16 image has it), and ChromaDB.

Can I try it before paying?

Yes. Lite is free, MIT-licensed and contains the same retrieval and citation code that Pro builds on.

What if it doesn't work for me?

Refund terms are shown at checkout. Before you buy, you can run Lite on your own documents to see how retrieval behaves on them.
